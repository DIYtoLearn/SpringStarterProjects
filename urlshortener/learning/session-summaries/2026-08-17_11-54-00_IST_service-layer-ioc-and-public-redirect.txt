What was learned
----------------
1. Why a service layer is needed
   A controller's main responsibility is the HTTP boundary: receive a request,
   read request data, call application logic, and form a response. The service
   holds reusable application/business operations. This separation lets API
   creation and public redirection share one implementation without copying
   maps or URL-generation code.

2. IoC and Spring beans
   Inversion of Control means the application does not explicitly construct and
   wire every collaborating object. Spring's application context discovers,
   creates, and manages participating objects. Such managed objects are beans.
   `@Service` is the appropriate stereotype for the URL-shortening service,
   making it discoverable as a Spring component.

3. Constructor dependency injection
   A controller declares its required collaborator as a constructor parameter:
   UrlShortenerService. Spring creates the controller and provides the matching
   service bean. With one constructor, no `@Autowired` annotation is needed.
   The final fields make the required dependency explicit and prevent later
   reassignment.

4. Java instance state and shared service state
   The learner correctly reasoned that calling `new UrlShortenerService()` in
   each controller would create two Java objects. Each object would own separate
   HashMap instances, so an API-created mapping would not be visible to the
   redirect controller. Constructor injection instead gives both controllers
   Spring's shared service bean in this application context.

5. Bidirectional map direction
   For duplicate creation, the long original URL is the key, so use:
   urlToShortCode.get(originalUrl).
   For redirect lookup, the short code is the key, so use:
   shortCodeToUrl.get(shortCode).
   Two reversed lookup attempts were found during review and corrected. They
   compiled because both keys and values are Strings, demonstrating that code
   compiling does not guarantee correct data semantics.

6. Route separation
   A method in a controller annotated with @RequestMapping("/api") always has
   `/api` in its effective route. Therefore `GET /api/{shortCode}` could not be
   the desired public `GET /{shortCode}` route. Moving the redirect handler to
   a separate controller without that class-level mapping produced the intended
   API/public-route separation.
