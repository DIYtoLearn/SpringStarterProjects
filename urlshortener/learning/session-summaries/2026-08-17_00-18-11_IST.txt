- GET /api/status returns the status message.

- CreateUrlRequest has a url property with standard getUrl and setUrl methods.
- A duplicate original URL returns its existing short link.
- A new original URL is assigned a nine-character alphanumeric short code.

- shortCodeToUrl supports short code -> original URL lookup.
- Both maps are populated for each new URL mapping and reset on application

- GET /api/{shortCode} looks up a code and returns either 302 Found with a

Topics covered
--------------
1. JSON request DTO binding
   @RequestBody CreateUrlRequest tells Spring to read the request body and
   convert its JSON into a CreateUrlRequest instance. The JSON property "url"
   is assigned through setUrl(...), then getUrl() returns its Java String.

2. Duplicate long-URL lookup
   urlToShortCode.containsKey(originalUrl) distinguishes a duplicate request
   from a new URL. get(originalUrl) retrieves the existing code without
   generating or storing another mapping.

3. Bidirectional in-memory storage
   A new mapping is stored in both maps because creation and redirection need
   opposite lookup directions.

4. Random short-code generation and collisions
   A generated code must be absent from shortCodeToUrl before it is stored.
   The first version retried only once; a second collision could still have
   overwritten a mapping. A do...while loop now repeats until the code is
   unique. Random.nextInt(origin, bound) excludes bound, so the ASCII bounds
   were corrected to include Z, z, and 9.

5. Path variables
   @GetMapping("/{shortCode}") captures one path segment, and
   @PathVariable String shortCode supplies that captured value to the method.
   Since this method is inside a class mapped to /api, the actual current route
   is /api/{shortCode}.

6. ResponseEntity and redirect responses
   ResponseEntity controls HTTP status, headers, and the optional body.
   A known code returns 302 Found and Location: <original URL>; the browser or
   HTTP client follows that header by making the next request itself. An
   unknown code returns 404 Not Found. ResponseEntity<Void> is appropriate
   because this redirect response has no body.

Misconceptions or corrections
-----------------------------
- Raw JSON text is not the same as the URL value inside it. A DTO is needed to
  receive the url property as a clean Java String.
- Checking one generated code a second time is not sufficient. Collisions must
  be checked repeatedly until a free code exists.
- Returning the destination URL with 200 OK is not a redirect. A redirect is a
  3xx response with a Location header.
- A method-level mapping is combined with the controller's class-level mapping.
  Therefore the current redirect is /api/{shortCode}, not /{shortCode}.
- In-memory maps are useful for this learning phase but their contents vanish
  after restart; plain HashMap controller state also needs redesign before
  concurrent production use.
